# Output schema v1

Every run writes a new directory; existing directories are rejected. Full campaign contains `gate/`, `2003/` … `2007/` and `campaign_summary.json`. Smoke runs never enter study aggregation.

* `metadata.json`: schema, status (`initializing`, `complete`, `failed`), error if failed, UUID, seed/profile, OS/architecture/CPU model, cores/affinity/quota, raw Linux cpuinfo, Python/package versions, GPU name/CC/UUID/driver/runtime, native OpenSSL version/capability mask/compiler/build/hash/import bindings, source hashes, runtime ID/fingerprint, thread configuration, and completed row/repetition counts.
* `sources/`: source snapshots at original repository-relative paths. Build manifest in native metadata includes exact compiler command/options and wrapper/library hashes. CUDA options are fixed `--std=c++11`; compilation uses NVRTC through recorded CuPy/runtime/toolkit configuration.
* `validation.json`: 25 successful cases, reference URLs, sizes/layouts, CPU/GPU validation flags and ciphertext hashes. A validation failure instead marks metadata failed; absence of this file is not a pass.
* `planned_order.json`: scheduled jobs. `execution.jsonl`: actual start/completion events with host epoch ns and job fields. Failed/incomplete events remain available.
* `inputs.jsonl`: one entry per logical layout/batch/round; plaintext/ciphertext SHA-256, synthetic key, explicit IV list, pairing digest. Plaintext is regenerated by `material` from seed/pages/repeat.
* `raw.jsonl`: each validated timing record flushed immediately. `raw.csv`: identical union of fields, written when all records complete; blanks represent unavailable metrics. JSONL is authoritative. Warm-ups remain raw. Full session 600 rows (120 warm-up, 480 measured); smoke 72 rows (24 warm-up, 48 measured).
* `summary.json`: session `boundaries`, `speedups`, `batch_scaling`, `page_over_continuous_throughput`. `campaign_summary.json`: distributions of session medians, both speedup estimators, favorable session counts and control contrasts.

Raw identity fields: `session_id`, `seed`, `execution_index`, `pages`, `bytes`, `repeat` (negative warm-up), `warmup`, `layout` (`pages`/`continuous`), `measurement` (`cpu`/`resident`/`pipeline`), `pair_id`, `pair_hash`, `plaintext_sha256`, `validated`.

`actual_ciphertext_sha256` records the observed output. A timed ciphertext mismatch is flushed to raw JSONL with `validated=false` before raising; aggregation rejects it. Earlier valid records remain intact. An exception inside the measurement itself has a started execution event but cannot supply a completed timing. NVRTC version, compile options and thread/OpenSSL environment settings are also recorded in metadata.

CPU metrics (integer ns): `cpu_transform_ns`, `cpu_operation_ns`, `setup_ns`, `cleanup_ns`, `allocation_ns`, `binding_ns`, `native_call_ns`, `native_residual_ns`, `output_copy_ns`. Native residual is signed. Operation contains nested diagnostics; do not sum operation and components.

GPU metrics: `kernel_ns` (floating ns converted from CUDA event milliseconds, not ns precision); pipeline also `end_to_end_ns`, `h2d_ns`, `d2h_ns`, `transfer_ns`, signed `pipeline_residual_ns`; resident also `resident_batch_ns` with one launch. Legacy derived `kernel_seconds`, `end_to_end_seconds`, `kernel_throughput_MB_s`, `end_to_end_throughput_MB_s` are preserved when provided. Pipeline's kernel observation is diagnostic and never substituted for the separately scheduled resident observation.

Throughput is `bytes * 1000 / ns` in decimal MB/s. Each boundary remains distinct, including transfer-only diagnostic throughput. Latency is full batch completion time within the named boundary, not per-page latency. No outlier removal, speedup clipping or replacement of negative residuals occurs. Statistics use inclusive quartiles, sample SD, CV as a fraction, and Tukey 1.5-IQR outlier counts.
