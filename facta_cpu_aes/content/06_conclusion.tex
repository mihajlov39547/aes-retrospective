\section{Conclusion}
\label{sec:conclusion}
This study examined how AES implementation choices and measurement scope affect CPU encryption throughput. The analyzed records show a strong dependence on the selected library path: at 32 MiB, default OpenSSL achieves approximately 4.03 GB/s on the measured Arm64 system, compared with 0.21--0.22 GB/s for the evaluated alternatives. On Windows, the OpenSSL-to-PyCryptodome throughput ratio decreases from approximately 1.93 for transformation to 1.23 for the instrumented operation. Separate CBC and GCM experiments show that key length and authenticated message processing introduce further workload-dependent effects.

Cipher throughput must therefore be interpreted for the software interface and cryptographic functionality relevant to the application. Implementation selection and surrounding software costs should be evaluated together. Although the numerical results are specific to the measured systems, the analysis provides a clearer basis for comparing encryption benchmarks. Matched native measurements and evaluation within storage or messaging services are needed to establish application-level benefits.
