Reported encryption throughput is not an intrinsic property of AES: it depends on instruction support, cryptographic-library dispatch, and the interval selected for timing. This paper re-examines existing, validated CPU measurements from a Windows x86-64 laptop and an Oracle Cloud Arm64 instance. In 32 MiB AES-128-CTR measurements, native OpenSSL EVP reaches approximately 4.03 GB/s on Arm64, versus 0.21--0.22 GB/s for the inspected alternative paths. On x86-64, accounting for allocation and output conversion substantially reduces the apparent gain of native encryption. Historical CBC and authenticated GCM measurements provide an independent perspective on key length, message size, and verification costs. The results support boundary-aware CPU benchmarking but do not establish instruction-level causation or a platform-wide architecture ranking.
