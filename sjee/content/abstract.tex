
High-throughput cryptographic processing is an important requirement in modern
telecommunications infrastructure, where GPU acceleration offers opportunities
for improving bulk data encryption. This study investigates the conditions
under which GPU-assisted AES-128 processing can provide measurable benefits
over hardware-accelerated CPU encryption. A validation-first experimental
approach evaluates AES in CTR and ECB modes across three heterogeneous
computing configurations, using paired workloads, five measurement sessions
per system, and separate device-resident and synchronous transfer-inclusive
GPU execution boundaries.
For 32~MiB AES-CTR workloads, the GPU processing pipeline achieves median
paired speedups of $1.354\times$ on the T600 Laptop GPU and $4.761\times$
on the Tesla T4 relative to their respective AES-NI CPU implementations,
with improvements observed in all five sessions. In contrast, the GTX
configuration achieves only $0.935\times$, demonstrating that acceleration
is not universally beneficial. The results establish experimentally
supported conditions under which GPU processing can improve bulk AES
throughput despite synchronous data transfers.
These findings provide experimental evidence that GPU-assisted AES-CTR
processing can improve bulk encryption throughput over hardware-accelerated
CPU execution, even when synchronous data transfers are included. The
demonstrated gains identify concrete opportunities for accelerating
cryptographic workloads in heterogeneous telecommunications systems,
although improvements in complete IPsec and authenticated network
processing remain to be established.
