\section{Conclusion}
Existing validated measurements from Windows x86-64 and Oracle Cloud Arm64 demonstrate that AES throughput is inseparable from the implementation path and the execution interval being timed. A native OpenSSL AES-128-CTR transform reached about 4.03 GB/s on the measured Arm64 system, whereas its inspected alternative paths were near 0.21--0.22 GB/s. On Windows, OpenSSL's 32 MiB inner transform achieved about 5.54 GB/s, but the wider operation envelope reduced reported throughput to about 1.48 GB/s. Additional CBC and GCM evidence illustrates key-length sensitivity and the cost profile of authenticated operations across message sizes. These observations do not rank processor architectures or isolate instruction-level causation. Their practical contribution is a reproducible way to interpret encryption benchmarks: every performance figure requires a specified cryptographic workload, implementation path, timing scope and replication unit.
